## 1. 设计目标与约束

### 1.1 要解决的问题

用户装了游戏/软件/压缩包后，磁盘空间逐渐减少，但**不知道空间去了哪里**，只能全盘慢扫。
本工具的核心主张是：**在写入发生的那一刻就记录落点**，把"事后全盘搜索"变成"平时自动记账"。

### 1.2 功能目标（对应需求）

| # | 需求 | 实现方式 | 状态 |
|---|---|---|---|
| 1 | 用户启动安装/解压程序时能自主察觉装到哪、占多大 | 三路信号融合（注册表台账 / 进程快照 / 目录 diff） | ✅ |
| 2 | 手动添加未察觉的文件位置与大小 | 内置路径浏览器 + 单文件支持 + 体检结果一键加入 | ✅ |
| 3 | 美观简洁的树状图，节点含名称与具体大小 | 目录树视图（懒加载、等宽数字、相对占比条） | ✅ |
| 4 | 只展示阈值以上的节点，阈值可由用户指定 | 服务端 SQL 过滤 + 滑杆/预设（10MB–50GB，对数刻度） | ✅ |
| 5 | 越大占更大面积但有上限 | 行高/字号/图标/条高按对数权重缩放并 clamp 到 1；矩形图面积严格等比 | ✅ |
| 6 | 颜色也能强调大小 | 六档热度色阶（青→薄荷→紫→品红→红） | ✅ |
| 7 | 对具体目录/文件做标注与备注 | 备注 + 标签 + 待清理标记，按路径键持久化 | ✅ |
| 8 | 丝滑动效 + 赛博朋克/黑客风配色 | 原生 CSS 动画、手风琴展开、错落入场、扫描线/网格背景、霓虹边框 | ✅ |

### 1.3 硬约束

- **只读**：不允许删除、移动、重命名用户文件（避免任何误删风险，也让安全审查变简单）
- **零联网**：全部本地；不引入 CDN、字体服务或遥测
- **零第三方依赖**：仅用 Python 标准库，避免 pip 安装失败导致"双击跑不起来"
- **不阻塞 UI**：所有扫描/体检在后台线程，前端轮询进度
- **可离屏运行**：无控制台启动也不能崩（stdout 句柄无效的坑见 §12.4）

## 2. 技术选型与取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| Electron + Node | UI 自由度最高 | 包体 100MB+、需要 node 运行时、构建链复杂 | ✗ |
| Tauri + Rust | 包体小 | 需要 Rust 工具链与 WebView2，构建门槛高 | ✗ |
| PyQt / Tkinter 桌面 | 单进程、原生 | 树形+动画+霓虹风格用 QSS 实现成本极高，视觉上限低 | ✗ |
| **Python 标准库 HTTP + 原生 Web UI** | 零依赖、浏览器渲染能力最强、UI 迭代快 | 需要用户有 Python（用启动器自动发现） | ✅ **采用** |
| 静态 HTML + File System Access API | 无需后端 | 浏览器沙箱无法可靠枚举磁盘/注册表/进程，且每次要授权目录 | ✗ |

### 关键取舍

1. **"本地网页"而非"原生窗口"**：需求允许，且换来 CSS/Canvas 级别的视觉表现力。
   用 `http://127.0.0.1:8765` 而不是 `file://`，因为需要后端 API 与跨请求状态。
2. **快照式索引而非实时遍历**：浏览时读 SQLite 快照（亚毫秒级），扫描只在必要时进行。
3. **单文件 SQLite 而非多文件 JSON**：事务、索引、并发读写、崩溃恢复都是现成的。
4. **无框架前端**：手写 ~1500 行 JS，避免构建步骤；得益于浏览器缓存与 `no-store`，改完刷新即生效。

## 4. 一次典型会话的时序

### 4.1 启动

```
SpaceSight.exe
  └─ 定位 python.exe → 设置 SPACESIGHT_LOG=1 → CreateNoWindow 启动 run.py
       └─ run.py: 重定向 stdout/stderr → data/server.log
            └─ server.main()
                 ├─ existing_instance(8765)? 是 → 打开浏览器并退出（防重复实例）
                 ├─ find_free_port(8765, +12)
                 ├─ Store(DB)  → 建表/迁移/写默认设置
                 ├─ App(store).start()  → 启动扫描工作线程
                 ├─ Detector.start()    → 立刻执行一次基线（静默）
                 ├─ ThreadingHTTPServer(127.0.0.1, port)
                 └─ 0.7s 后 webbrowser.open(url)
```

### 4.2 添加一个追踪目标

```
前端 POST /api/roots {path}
  → 校验存在性 → 归一化路径 → 计算路径键 → 去重
  → roots INSERT (status=pending, is_new=1)
  → store.add_event("track")
  → App.start_scan(root_id) → JobRegistry.new("scan") → scan_queue.put()
  → 立即返回 {root, job}

扫描工作线程：
  → scanner.scan_root(store, root, job, cfg)
      ├─ store.clear_nodes(root_id)
      ├─ 列出顶层子项（跳过重解析点）
      ├─ 文件子项直接计入；目录子项用 ThreadPoolExecutor 并行扫描
      ├─ DbSink 每 5000 行批量 INSERT（WAL，单事务）
      └─ 回写 roots(total_bytes, file_count, dir_count, scan_ms, status=ready)
  → store.add_event("scan", message="扫描完成：xx GB / N 文件 / T ms")

前端（700ms 轮询 /api/jobs/{id}）
  → 完成后 refreshState() + refreshRootTree(rootId) 局部刷新，不整页重绘
```

### 4.3 安装检测 → 自动追踪

```
Detector 线程 (每 5s) poll_registry()
  → 读 HKLM/HKCU Uninstall → 与 apps 表比对
  → 发现新条目 → upsert_app(mark_new=True) → store.add_event("install")
  → App.on_install_detected(entry)
       ├─ auto_track 开启 && 路径存在 && 非系统目录 && 未追踪
       ├─ store.add_root(source="registry", is_new=1)
       ├─ store.track_app() 建立台账↔追踪目标关联
       └─ start_scan() → 自动测量真实占用
前端 pollEvents(3.2s) → 新事件滑入 + toast 提示
```

## 5. 数据模型

### 5.1 表结构

```sql
-- 追踪目标
CREATE TABLE roots(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  key TEXT NOT NULL UNIQUE,      -- 路径键（小写、规范化），用于去重与关联
  path TEXT NOT NULL,            -- 原始大小写路径，用于展示/打开
  label TEXT NOT NULL,
  kind TEXT NOT NULL,            -- folder | drive | file
  source TEXT NOT NULL,          -- manual | registry | detector
  meta TEXT NOT NULL DEFAULT '{}',  -- JSON：版本/发行商/来源父目录等
  is_new INTEGER NOT NULL DEFAULT 0,
  pinned INTEGER NOT NULL DEFAULT 0,
  status TEXT NOT NULL,          -- pending | scanning | ready | missing | error | partial
  scanned_at TEXT,
  total_bytes INTEGER NOT NULL DEFAULT 0,
  file_count INTEGER NOT NULL DEFAULT 0,
  dir_count INTEGER NOT NULL DEFAULT 0,
  scan_ms INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL
);

-- 扫描快照（扁平存储，按 parent_key 建索引，模拟树）
CREATE TABLE nodes(
  root_id INTEGER NOT NULL,
  key TEXT NOT NULL,             -- 本节点路径键
  path TEXT NOT NULL,            -- 本节点显示路径
  parent_key TEXT NOT NULL,
  name TEXT NOT NULL,
  is_dir INTEGER NOT NULL,
  size INTEGER NOT NULL,         -- 目录=子树总字节；文件=自身大小
  files INTEGER NOT NULL,        -- 子树文件数
  dirs INTEGER NOT NULL,         -- 子树子目录数
  mtime REAL NOT NULL,
  depth INTEGER NOT NULL,
  PRIMARY KEY(root_id, key)
) WITHOUT ROWID;

CREATE INDEX idx_nodes_parent ON nodes(root_id, parent_key, size DESC);
CREATE INDEX idx_nodes_size   ON nodes(root_id, size DESC);
CREATE INDEX idx_nodes_name   ON nodes(root_id, name);

-- 用户标注（按路径键，与追踪目标解耦）
CREATE TABLE notes(
  key TEXT PRIMARY KEY, path TEXT NOT NULL,
  note TEXT DEFAULT '', tags TEXT DEFAULT '', flagged INTEGER DEFAULT 0,
  updated_at TEXT NOT NULL
);

-- 察觉事件流
CREATE TABLE events(id INTEGER PRIMARY KEY AUTOINCREMENT, ts TEXT, kind TEXT,
                    path TEXT, label TEXT, size INTEGER, message TEXT);

-- 注册表安装台账
CREATE TABLE apps(key TEXT PRIMARY KEY, name TEXT, path TEXT, size INTEGER,
                  version TEXT, publisher TEXT, install_date TEXT, reg_key TEXT,
                  root_id INTEGER, first_seen TEXT, last_seen TEXT, is_new INTEGER);

-- 键值设置
CREATE TABLE settings(k TEXT PRIMARY KEY, v TEXT NOT NULL);
```

### 5.2 三个关键设计决策

**(a) 为什么 nodes 是扁平表而不是嵌套 JSON？**

- 可增量写入（扫描边扫边落库，内存只与"单个顶层子树"相关）
- 单层查询即得子项，`(root_id, parent_key, size DESC)` 索引让"取最大 N 个子项"变成索引区间扫描
- 换根/删除目标只需 `DELETE WHERE root_id=?`
- 代价：每行冗余存了 `path` 与 `parent_key`（约 0.9 KB/节点，见 §11）

**(b) 为什么用"路径键"而不是外键关联？**

Windows 路径大小写不敏感，`D:\Games` 与 `d:\games` 是同一目录。
`pkey(path) = normpath(abspath(path)).lower()` 作为逻辑主键，可保证：

- 同一个目录不会重复追踪（`roots.key UNIQUE`）
- 标注可以在**没有**对应节点时存在（先备注、后扫描也能恢复）
- 删除追踪目标不会丢标注

**(c) 目录大小存在节点自身**

每个目录行直接存"子树总字节 + 子树文件数 + 子树子目录数"，
所以 UI 展示任意目录的大小是一次主键查询，**O(1)**，无需递归。

### 5.3 索引与查询

```sql
-- 取某层子项（阈值过滤 + 大小排序 + 分页）：走 idx_nodes_parent
SELECT * FROM nodes
 WHERE root_id=? AND parent_key=? AND size>=?
 ORDER BY size DESC, name ASC
 LIMIT ? OFFSET ?;

-- 全局/单根名称搜索：走 idx_nodes_name（LIKE 前缀用不上索引，但节点量级可接受）
SELECT * FROM nodes WHERE name LIKE ? AND size>=? ORDER BY size DESC LIMIT ?;
```

## 6. 扫描引擎

### 6.1 为什么不用 `os.walk`

`os.walk` 是自顶向下生成器，天然拿不到"目录总大小"（需要额外一趟或自底向上）。
本工具需要**一趟遍历同时得到每个目录的完整子树大小**，因此采用
**显式栈 + 帧（frame）+ 后序聚合**：

```python
class _Frame:            # 一个"正在遍历的目录"
    path, key, name, depth, parent_key
    size, files, dirs, mtime
    it                   # os.scandir 迭代器

stack = [root_frame]
while stack:
    f = stack[-1]
    try:
        entry = next(f.it)
    except StopIteration:          # 本目录遍历完 → 收口
        _finalize(stack, ctx)      # 落库自身节点 + 把统计回填父帧
        continue
    st = entry.stat(follow_symlinks=False)
    if is_reparse(st): continue    # 跳过 junction / symlink，避免回环与重复计数
    if is_dir(st):
        stack.append(open_frame(entry))   # 压栈，先不计数
    else:
        f.size += st.st_size
        f.files += 1
        if st.st_size >= min_keep: sink.add(file_row)
```

优势：

- **无递归深度限制**（`C:\` 下上千层深的临时目录也不会 RecursionError）
- **内存 O(深度)**，不是 O(节点数)
- **一处统计、一处落库**，逻辑只有一份

### 6.2 并行策略

只有**顶层子目录**之间并行（磁盘 I/O 密集，4 线程通常快 2–3 倍）：

```python
workers = min(scan_workers, len(dir_children))
with ThreadPoolExecutor(max_workers=workers) as pool:
    for size, files, dirs in pool.map(_one, dir_children):
        total_bytes += size; ...
```

刻意不做深层并行：机械硬盘上过多并发寻道反而更慢；SSD 上 4 线程已接近带宽上限。
扫描任务本身在**单线程队列**里串行执行（多个目标同时扫会互相抢盘），保证交互流畅。

### 6.3 边界处理

| 情况 | 处理 |
|---|---|
| 权限拒绝（`OSError` on scandir/stat） | 计 `denied` 计数，跳过该目录，扫描继续 |
| 重解析点（junction / symlink） | `st_file_attributes & 0x400` → 完全跳过（防 `All Users` 之类的回环） |
| 设备/管道/套接字 | 非 `S_ISDIR`/`S_ISREG`，忽略 |
| 盘符根目录 | 额外跳过 `$Recycle.Bin` `System Volume Information` `Recovery` 等噪声目录 |
| 路径过长（>260） | 依赖 Python 3.6+ 的 long path 支持；失败则计 denied |
| 单文件作为追踪目标 | 直接写一行节点，`parent_key=''` |
| 目标被删除 | `roots.status='missing'`，UI 显示红色"缺失"标记 |
| 节点数爆炸 | `max_nodes=600000`，超出后停止记录（大小仍准确），任务标记 `warning` |
| 用户取消 | `Job.cancelled` 在每个循环迭代检查，落库已扫部分，状态置 `partial` |

### 6.4 写入路径

```python
class DbSink:                    # 线程安全批量写
    def add(row):
        with self.lock:
            rows.append(row)
            if len(rows) >= 5000: flush()
    def flush():
        store.insert_nodes(root_id, rows)   # executemany + 单事务
```

`nodes` 表使用 `PRAGMA journal_mode=WAL` + `synchronous=NORMAL`：
写入吞吐高，且读请求（前端浏览）不会被扫描事务阻塞。

### 6.5 体检模式（Audit）

复用同一套 DFS，但换一个 Sink：

```python
class AuditSink:             # 不落库，只维护两个大小为 top_n 的小顶堆
    files: heap[(size, path, name, files, mtime, depth)]
    dirs:  heap[...]
    def add(row):
        if is_dir and depth == 0: return     # 体检根自身不计入 Top 目录
        heap = files if not is_dir else dirs
        if len(heap) < top_n: heappush(item)
        elif item[0] > heap[0][0]: heapreplace(item)
```

内存 O(top_n)，可安全地对整个磁盘做体检；结束后按 size 降序返回。

## 7. 安装察觉子系统

### 7.1 信号一：注册表安装台账

读取三个位置（64/32 位视图与用户级）：

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*
HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*
HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*
```

对每个子键取：`DisplayName`、`InstallLocation`、`EstimatedSize`(KB)、`DisplayVersion`、
`Publisher`、`InstallDate`，并过滤噪声：

```python
if not display: skip                             # 无名条目
if SystemComponent == 1: skip                    # 系统组件
if ParentKeyName: skip                           # 补丁子项
if _UPDATE_NAME_RE.match(display): skip          # "Security Update for…" "KB50xxxx" 等
```

**基线机制**：`settings.apps_baseline_done` 为 0 时，首轮导入全部条目但 `is_new=0`（不刷屏）；
之后每轮新出现的条目 `is_new=1` 并触发事件与自动追踪。
`upsert_app` 在更新已有条目时**不修改** `is_new`，否则每 5 秒轮询都会把 NEW 重新点亮（已修复的一个真实缺陷）。

**为什么用 `EstimatedSize` 只作参考**：它是安装器写入的 KB 估算值，不包含后续更新、
存档、缓存。自动追踪会用真实扫描结果覆盖 UI 显示。

### 7.2 信号二：安装/解压进程监控

用 Toolhelp32 快照枚举进程名（纯 `ctypes`，无需 WMI/管理员权限，单次 <1 ms）：

```python
k32.CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0)
while Process32NextW(...): names.add(entry.szExeFile.lower())
```

特征匹配：

```python
INSTALLER_RE = (setup|install|unpack|extract|expand|msiexec|inno|nsis|dxsetup|
                vc_redist|dotnetfx|bundle|7zg|7zfm|winrar|unrar|bandizip|
                peazip|haozip|360zip|patcher|update_|_update|updater)
INSTALLER_EXCLUDE_RE = (unins|trustedinstaller|tiworker|usoclient|wusa|wuauclt|
                        musnotification|crashpad|…)
```

命中后：

1. 对"常用安装位置"拍快照（`Program Files`、`Program Files (x86)`、`%LOCALAPPDATA%`、
   `%APPDATA%`、`%ProgramData%`、各固定磁盘根的一级子项名字集合）
2. 记录 `installer_snapshots[进程名] = snapshot`
3. 进程消失 → 重新列举 → `current - old` 得到新目录
4. 触发 `store.add_event("folder")` 与 `on_folder()`（自动追踪 + 扫描）

这条路径覆盖**绿色版 / 免安装 / 解压型**程序（它们不写注册表，但一定建目录）。

### 7.3 信号三：目录变更侦测（三种模式）

监控目标 = 常用安装位置 + 固定磁盘根 + **所有追踪目标本身**。每个目标带一个模式：

```python
# add    = 出现新目录 → 自动纳入追踪（真正装软件的地方）
# notify = 只写事件，不自动追踪（AppData / ProgramData 变化过于频繁）
# rescan = 追踪根内出现新内容 → 重扫该根
targets = [(dir, "add", 0), (localappdata, "notify", 0), ..., (root.path, "rescan", root.id)]
```

| 模式 | 覆盖路径 | 行为 |
|---|---|---|
| `add` | `Program Files`、`Program Files (x86)`、`%LOCALAPPDATA%\Programs`、各固定磁盘根 | 新目录 → `on_folder` → 自动追踪 + 扫描 |
| `notify` | `%LOCALAPPDATA%`、`%APPDATA%`、`%ProgramData%` | 只写 `folder` / `bigfile` 事件，不追踪 |
| `rescan` | 每个已追踪目录 | 出现新内容 → `on_root_change` → 重扫该根 |

- 位置不在上一轮基线里（新纳入监视）→ **只建立基线，不报告变化**（避免"刚加追踪就报一堆新内容"）
- 同一根重扫有 60 秒节流；`change` 事件另有 10 分钟节流，避免 VS Code 配置目录这类高频写入刷屏
- 重扫完成时若大小变化 < max(5%, 100MB)，不再写 `scan` 事件（静默更新数据）
- 这样不会把子目录重复列为独立目标，也不会产生"父目录 + 子目录"双重计数的错觉

### 7.4 去噪清单

```python
SKIP_DIR_NAMES = {$recycle.bin, system volume information, config.msi, $winreagent,
                  recovery, perflogs, documents and settings, windows.old, temp, tmp,
                  node_modules, .git, $sysreset, found.000, onedrivetemp, msdownld.tmp}
SKIP_DIR_PREFIX = ("$", "~", ".", "ntuser")
NO_AUTO_TRACK  = {C:\, C:\Windows, C:\Program Files, C:\Program Files (x86), C:\ProgramData, C:\Users}
```

另外 `auto_track=0` 时只记录事件与台账，不自动往追踪列表里塞。

**自动追踪的三道闸门**（`App._auto_track_allowed` + 扫描完成后处理）：

1. **重叠拒绝**：目标路径等于/位于/包含任一已有追踪根 → 不追踪（否则同一份空间会被算两遍）。
   实测反例：`%LOCALAPPDATA%\Programs` 已在追踪，注册表又把
   `%LOCALAPPDATA%\Programs\Microsoft VS Code` 加进来，导致 1.6GB 被重复计入总量。
2. **小目标撤回**：`source='detector'` 的目标扫描后若 < `MIN_AUTO_TRACK_BYTES`(300MB)，
   自动 `delete_root` 并记 `UNTRACK` 事件（AppData 碎片实测 0MB / 40MB 各一例）。
3. **模式分流**：`notify` 位置的新目录只记录事件（见 §7.3）。

### 7.5 为什么这是"概率性"的（诚实的局限）

| 漏检场景 | 根因 | 兜底 |
|---|---|---|
| 单文件绿色程序 | 无目录、无注册表 | 手动添加文件 |
| 安装进已存在的深层目录 | 只比对一级子项 | 手动 `↻` 重扫，或选中子目录 `＋ 单独追踪` |
| 安装期间程序退出 | 侦测线程随进程结束 | 重启后「立即侦查安装」 |
| 安装器未退出就结束 | 快照比对未触发 | 同上 |
| 注册表不提供 InstallLocation | 只能出现在台账 | 在台账里看路径，手动添加 |

不做重活（USN Journal / MFT 解析）的原因：需要管理员权限、实现复杂、且与"只读、双击即用"的定位冲突。
这些列在路线图里（§16）。

## 8. HTTP 服务与 API

### 8.1 服务实现

- `ThreadingHTTPServer` + `BaseHTTPRequestHandler`，`protocol_version = HTTP/1.1`
- 请求解析：`urlparse` 取 path/query；JSON body 上限 8MB，解析失败按空对象处理（不 500）
- 静态文件：`os.path.realpath` 前缀校验防目录穿越；`Cache-Control: no-store` 便于迭代
- 错误统一：`{"ok": false, "error": "..."}` + 合适状态码；handler 顶层 try/except 打印回溯
- `log_message` 静默访问日志（控制台只留业务输出）

### 8.3 任务模型

```python
class Job:
    id, kind("scan"|"audit"), status("running"|"done"|"error"|"cancelled")
    files, dirs, bytes, current, message, warning, error
    result{}, extra{}          # extra.root_id 供前端知道该刷新哪个根
    cancel() / cancelled       # threading.Event
    snapshot()                 # 加锁返回可 JSON 序列化的快照
```

前端只对"自己发起的"任务做 700ms 轮询，避免无意义的广播。
扫描进度推送被限流到 250ms 一次（`ScanContext.tick`），避免高频锁竞争。

## 9. 前端实现

### 9.1 状态与数据流

```js
const S = {
  settings, roots, rootMap, activeRoot, view,
  treeCache: Map<"rootId:key", {children, hidden, total, parent}>,
  expanded: Set<"rootId:key">,
  selected: {rootId, key, path},
  apps, events, maxEventId, threshold, detector, disk, totals
};
```

- 所有数据来自 REST，前端**不持久化**任何业务状态（除 URL hash 的视图名）
- 轮询：事件流 3.2s；全局状态 7s；任务 0.7s（仅活跃任务）；页面隐藏时全部跳过
- 局部刷新：扫描完成后只重建该根的子树（`refreshRootTree`），不整页重绘

### 9.2 目录树的懒渲染

- 每个节点是 `<div class="node"><div class="row">…</div><div class="kids">…</div></div>`
- 展开时才请求 `/api/tree`，结果缓存在 `treeCache`，折叠再展开不重复请求
- 每层最多渲染 400 项，超出显示「＋ 显示更多（共 N 项）」，按 offset 追加
- 低于阈值被过滤的项折叠成一行提示「⋯ 另有 N 项小于当前阈值」
- 事件委托（`#tree` 上一个 click listener）而非逐行绑定，数千行也不掉帧

### 9.3 手风琴展开动画

```js
function openKids(nodeEl, open) {
  const kids = nodeEl.querySelector(':scope > .kids');
  if (open) {
    kids.style.height = 'auto';
    chev.classList.add('open');
  } else {
    kids.style.height = kids.scrollHeight + 'px';   // 先固定当前高度
    void kids.offsetHeight;                          // 强制 reflow
    kids.style.height = '0px';                       // 再过渡到 0
  }
}
```

配合 `transition: height .28s cubic-bezier(.2,.85,.2,1)`，展开/收起都是连续的。
入场用 `rowIn` 关键帧 + 逐行 `animation-delay`（上限 260ms）实现错落感。

### 9.4 矩形图：Squarified Treemap

> **单根模型**：矩形图一次只渲染**一个**追踪目标，根由 `S.tmRootId` 记录。
> `focusRoot(id)` 统一维护 `activeRoot`（左侧高亮）与 `tmRootId`（矩形图根），
> 在「选中树节点 / 点左侧卡片 / 新增目标」时同步调用，并在 `refreshState()` 里校验
> `tmRootId` 是否仍然存在。早期版本只在切标签页时重绘，导致"手动添加目标后矩形图没反应"——已修复。

用 Bruls/Huizing/van Wijk 的 squarify 算法，追求**接近正方形的方块**（比 slice-and-dice 更易读）：

```js
function squarify(items, x, y, w, h) {
  // 每次沿较短边铺一行，用"最差长宽比"决定是否继续往这一行加项
  let worst = rowRatio(row, area, scale, side);
  while (next 使得 worst 变好) row.push(next);
  // 放置该行：width/height 按面积比例分配，最后一个填补余量
}
```

- 面积 **严格正比**于字节数（先按 `value/total * 可用面积` 折算）
- 递归两层：一级方块内留出标签区，再对子项布局
- 定位全部用**百分比**（`left/top/width/height` 相对容器），容器尺寸变化时自动填满
- `ResizeObserver` 监听容器尺寸，窗口/字体变化后重排
- 双击下钻（改 `S.tmPath` 后重取数据），面包屑回退

### 9.5 安全

- 所有插入 HTML 的字符串经 `esc()`（`& < > " '` 转义）——路径来自文件系统，必须视为不可信输入
- 不使用 `innerHTML` 拼接用户备注（备注写入 `<textarea>.value`）
- 无 `eval` / 无动态脚本注入；无外部资源请求（离线可用）

### 10.2 面积/尺寸（相对大小，带上限）

**行内权重**（同一层内比较，对数归一化）：

```js
w = clamp((ln(size) - ln(threshold)) / (ln(maxSibling) - ln(threshold * 1.5)), 0, 1);
```

`w` 驱动四件事（全部**有上限**，防止单个超大节点吃掉所有视觉空间）：

| 属性 | 映射 | 上限 |
|---|---|---|
| 行内边距 | `3.5px + w*3.5px` | 7px |
| 字号 | `12px + w*2.6px` | ≈14.6px |
| 图标字号 | `11px + w*6px` | 17px |
| 占比条高度 | `4px + w*7px` | 11px |
| 发光半径 | `0 + w*14px` | 14px |

**矩形图**则完全按面积线性等比（这是最"诚实"的空间隐喻），不做上限压缩，因为它本身就能容纳极大差异。

### 10.3 排版与氛围

- 数字一律等宽（`font-variant-numeric: tabular-nums`），列对齐不跳动

## 11. 性能实测

测试机：Windows 11 + NVMe SSD（热缓存），Python 3.12，4 扫描线程。换机器差异较大，主要取决于磁盘类型与缓存状态。

### 扫描吞吐

| 目标 | 文件数 | 目录数 | 占用 | 耗时 | 吞吐 |
|---|---:|---:|---:|---:|---:|
| 演示样本（浅层） | 24 | 35 | 26.4 GB | 7 ms | — |
| `C:\Program Files (x86)` 下某大目录 | 4 231 | 315 | 4.82 GB | 108 ms | ≈39 000 文件/秒 |
| `%LOCALAPPDATA%\Programs`（深层小文件为主） | 9 772 | 1 144 | 0.99 GB | 304 ms | ≈32 000 文件/秒 |

> 冷缓存（首次访问、机械硬盘）会慢 5–20 倍；扫描耗时主要取决于**元数据 syscall 次数**而非文件大小。

### API 延迟（本地回环，Python `urllib` 客户端，30 次采样）

| 接口 | p50 | p95 |
|---|---:|---:|
| `GET /api/state` | 0.84 ms | 0.99 ms |
| `GET /api/tree`（315 子目录层） | 0.76 ms | 0.85 ms |
| `GET /api/treemap?depth=2` | 1.12 ms | 18.73 ms |
| `GET /api/search` | 1.07 ms | 2.79 ms |
| `GET /api/apps`（43 条台账） | 0.84 ms | 1.07 ms |
| `GET /`（HTML） | 1.04 ms | 1.36 ms |

`treemap?depth=2` 的 p95 抖动来自"对 70 个一级项各查一次子项"（70 次主键索引查询）。

### 存储占用

- 实测：3 735 个节点 → 3.30 MB（VACUUM 后），≈ **0.9 KB/节点**（含两个索引与台账/事件表）
- 换算：10 万节点约 90 MB；一般用户 3–10 个追踪目标、数万节点，库在 10–50 MB 量级
- 冗余主要来自每行重复存储完整 `path` 与 `parent_key`（换取查询简单）；路线图中有优化方案

### 前端

- 单层 400 行渲染 ≈ 15–25 ms；千行以内滚动稳定 60fps（无虚拟滚动，靠事件委托与懒渲染）
- 全部资源（HTML+CSS+JS）约 100 KB 未压缩，无外部请求，冷启动首屏 < 300 ms

## 12. 可靠性、错误处理与并发

### 12.1 线程模型

| 线程 | 数量 | 职责 |
|---|---|---|
| HTTP 处理线程 | 每请求一个（daemon） | 路由、查库、读静态文件 |
| 扫描工作线程 | 1 | 串行执行队列里的 scan 任务 |
| 扫描内部线程池 | ≤4 | 顶层子目录并行 |
| 察觉线程 | 1 | 注册表/进程/目录轮询 |
| 体检线程 | 每任务 1（daemon） | 只读遍历，不写库 |

### 12.2 并发安全

- SQLite 连接 `check_same_thread=False` + 全局 `RLock`；WAL 模式下读写不互相阻塞
- `Job` 内部 `Lock`；`JobRegistry` 独立 `Lock`；`DbSink` 批量缓冲有锁
- 同一目标的重复扫描请求复用运行中的 Job（不会双扫）

### 12.3 失败处理

| 失败 | 行为 |
|---|---|
| 目标路径消失 | `status='missing'`，事件记录；UI 红色标记，可重扫恢复 |
| 扫描中抛异常 | `job.fail()` + 事件 `error` + 回溯打印到 stdout/日志；已扫数据保留 |
| 注册表不可读 | `/api/apps` 返回 `registry_ok:false`，UI 降级提示 |
| 端口被占 | 自动顺延 12 个端口；若发现已有实例则直接打开浏览器 |
| 前端 API 报错 | `toast()` 提示，不破坏已渲染视图 |
| 浏览器断开 | `BrokenPipeError` 静默吞掉，服务继续 |

### 12.4 一个真实的坑：无控制台启动

`SpaceSight.exe` 以 `CreateNoWindow + UseShellExecute=false` 启动 `python.exe` 时，
**stdout 句柄无效**，Python 里 `sys.stdout` 可能是 `None`，任何 `print()` 都会抛异常。
解决办法是在 `run.py` **最顶部**（任何 print 之前）判断 `SPACESIGHT_LOG` 环境变量并把
`sys.stdout/stderr` 重定向到 `data/server.log`：

```python
if os.environ.get("SPACESIGHT_LOG"):
    _log = open(os.path.join(BASE, "data", "server.log"), "a", encoding="utf-8", buffering=1)
    sys.stdout = sys.stderr = _log
```

### 12.5 卸载/退出

- `POST /api/shutdown` → 后台线程 `httpd.shutdown()` → 关闭 detector、flush、`store.close()`
- Ctrl+C 同样走 `finally` 分支，写入一条 `system` 事件后退出
- 不使用任何系统服务/计划任务，删除目录即彻底卸载

| 认证 | 无（本地单用户模型）；若需局域网使用需自行加反向代理与鉴权 |

| 命令执行 | 仅两处：`os.startfile(path)` 与 `explorer /select,<path>`；参数来自已校验存在的路径，不拼接 shell 字符串 |
| 目录穿越 | 静态文件服务用 `realpath` 前缀校验 |
| 请求体 | 上限 8 MB，JSON 解析失败按空对象处理 |
| 前端 XSS | 所有动态文本经 `esc()`；备注用 `.value` 写入而非 innerHTML |
| 注册表 | 只读（`KEY_READ`），不写任何键 |
| 进程 | 只枚举，不注入、不结束、不挂起 |
| 隐私 | 无遥测、无网络上报；所有数据留在本机 `data/spacesight.db` |

## 14. 构建、打包与分发

### 14.1 组成

```
SpaceSight.exe        ← csc 编译的 WinForms 启动器（6 KB，仅 Windows）
run.py                ← Python 入口（含日志重定向）
app/  web/  docs/     ← 源码与资源
data/                 ← 运行时生成
```

### 14.2 启动器编译

```bat
csc /nologo /target:winexe /optimize+ /out:SpaceSight.exe ^
    /r:System.Windows.Forms.dll /r:System.Drawing.dll tools\Launcher.cs
```

`Launcher.cs` 的 Python 发现顺序：

1. `<程序目录>\runtime\python.exe`（可选便携运行时 → 完全自包含）
2. `PATH` 中的 `python.exe`
3. `%LOCALAPPDATA%\Programs\Python\Python3*\python.exe`（取版本号最大者）
4. `%USERPROFILE%\.dsh\...\python.exe`（开发机内置运行时兜底）

失败时弹 MessageBox 给出安装指引，而不是静默退出。

### 14.3 完全自包含（可选）

若不想让用户装 Python，可二选一：

- **便携运行时**：把官方 embeddable 包解压为 `<程序目录>\runtime\`（含 `python.exe` 与 `python3xx.dll`），
  启动器会自动优先使用它，无需改代码
- **PyInstaller**：`pyinstaller --noconsole --add-data "web;web" run.py`，注意把 `BASE_DIR` 解析改为
  `sys._MEIPASS`；本仓库未内置该脚本（因构建环境无网络）

### 14.4 端口与实例管理

- 默认 8765；被占用则顺延（最多 12 个），实际端口写入 `data/server.port`
- 启动前 `GET /api/health` 探测；若已有 SpaceSight 在跑 → 只打开浏览器并退出

## 16. 已知限制与路线图

### 当前限制

1. **仅 Windows**：注册表、Toolhelp32、盘符枚举均为 Win32；Linux/macOS 需替换 `detectors.py` 与 `chosen` 路径逻辑
2. **察觉是启发式的**：见 §7.5，不能保证 100% 捕获
3. **硬链接重复计数**：`C:\Windows\WinSxS` 等目录数字偏大
4. **快照下限 64 KB**：更小的文件不进入索引
5. **单表冗余路径**：约 0.9 KB/节点，十万节点 ≈ 90 MB
6. **无删除功能**（设计选择）：清理动作仍需用户在资源管理器完成
7. **无虚拟滚动**：单层 >2000 行时会略卡（已用 400 行分页规避）
8. **无认证**：仅适用于本机单用户

### 路线图

| 优先级 | 事项 | 说明 |
|---|---|---|
| P0 | USN Journal / MFT 索引 | `fsutil usn` 或 `DeviceIoControl`，实现全盘秒级首扫（需管理员） |
| P0 | Steam / Epic / GOG 库解析 | 从 `libraryfolders.vdf` 与 `manifests/*.acf` 直接读游戏清单与安装路径 |
| P1 | 目录增长趋势 | 保存历史快照，展示"这个月谁长了 20GB" |
| P1 | 快照对比 | 两次扫描 diff，输出新增/删除/变化的文件清单 |
| P1 | 右键菜单集成 | 资源管理器"Send to SpaceSight" |
| P2 | 虚拟滚动 | 十万级节点单层浏览 |
| P2 | 导出 CSV / 分享报告 | 生成可读的清理建议报告（HTML/PDF） |
| P2 | 路径压缩存储 | `parent_id` 替代 `parent_key`，节点体积降 60% |
