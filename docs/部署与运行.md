# 部署与运行

> 面向"第一次拿到这个项目"的人。照着做，5 分钟内能跑起来。
> 服务只在本机运行，不联网、不需要管理员权限、不需要数据库服务器。

---

## 0. 你需要什么

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / Windows 11（64 位） |
| Python | **3.9 或更高**（只需要标准库，**不用 pip install 任何东西**） |
| 浏览器 | Edge / Chrome / Firefox 任一（界面就是本地网页） |
| 磁盘空间 | 源码 < 3MB；运行时数据库随追踪目标增长（10 万节点约 90MB） |
| 权限 | 普通用户即可（不写注册表、不改系统设置） |

## 1. 方式 A：下载 ZIP + 双击启动（推荐给普通用户）

### 1.1 装 Python

1. 打开 <https://www.python.org/downloads/windows/>，下载 **Python 3.12** 的 64-bit installer
2. 运行安装包，**第一屏务必勾选 `Add python.exe to PATH`**，再点 `Install Now`
3. 装完可以打开"命令提示符"验证：

   ```bat
   python --version
   ```
   应输出 `Python 3.12.x`。

   > 如果输出的是 `Python was not found; run without arguments to install from the Microsoft Store...`，
   > 说明你打到的是 **Microsoft Store 的占位别名**，不是真的 Python。
   > 两种解决办法：① 设置 → 应用 → 高级应用设置 → 应用执行别名，把 `python.exe` / `python3.exe` 关掉；
   > ② 重新运行安装包，勾选 Add to PATH 并选择 "Install for all users"。

### 1.2 拿到代码

在 GitHub 页面点 **Code → Download ZIP**，解压到任意目录（例如 `D:\Tools\SpaceSight`）。

> 解压路径**不要**包含奇怪字符；中文路径是可以的。

### 1.3 启动

双击 **`start-spacesight.bat`**。

会弹出一个控制台窗口并打印：

```
   ███████╗██████╗  █████╗  ██████╗███████╗███████╗██╗ ██████╗ ██╗  ██╗████████╗
   ...
   // 空间探针 · STORAGE CARTOGRAPHY  v1.0.x
   ─────────────────────────────────────────────────────────────────────
   ◈ 界面地址   http://127.0.0.1:8765/
   ◈ 数据文件   D:\Tools\SpaceSight\data\spacesight.db
   ◈ 关闭服务   在界面右上角点击「停机」/ 或按 Ctrl+C
```

浏览器会自动打开 <http://127.0.0.1:8765/>。
**这个控制台窗口就是服务本体，关掉它服务就停了。**

### 1.4 第一次使用

1. 点右上角 **「＋ 添加追踪」**
2. 用内置浏览器选择目录（例如 `D:\Games`），或直接粘贴路径
3. 点 **「添加并扫描」**，等底部进度条走完

之后每次你安装软件 / 解压压缩包，20 秒内就会在左侧「追踪目标」里自动出现新目标。

## 2. 方式 B：git clone（开发者）

```bat
git clone https://github.com/<你的用户名>/spacesight.git
cd spacesight
python run.py
```

常用参数：

```bat
python run.py --port 8899          :: 换端口（默认 8765，被占用会自动顺延）
python run.py --no-browser         :: 不自动开浏览器（服务器/远程桌面场景）
python run.py --data-dir D:\ss-data :: 用另一套数据目录（多份独立索引）
python run.py --help
```

## 3. 方式 C：编译成无黑窗口的 exe

想要"双击一个图标就打开、没有控制台"的体验：

1. 双击 **`tools\build-launcher.bat`**
2. 它用 Windows 自带的 .NET Framework 编译器（`csc.exe`）把 `tools\Launcher.cs` 编译成 `SpaceSight.exe`
3. 双击 `SpaceSight.exe` 即可

- 启动器会自动寻找可用的 Python（程序目录 `runtime\` → PATH → `%LOCALAPPDATA%\Programs\Python` → 开发工具链自带运行时），
  并**跳过 Microsoft Store 的假 python**（0 字节占位别名）
- 找不到 Python 时会弹窗提示；每次启动的决策记录在 `data\launcher.log`
- 想强制指定解释器：设置环境变量 `SPACESIGHT_PYTHON=D:\Python312\python.exe`（优先级最高）
- 无控制台启动时，服务日志写入 `data\server.log`

## 4. 方式 D：完全免安装的便携 Python（可选）

不想在系统里装 Python，可以做一个"绿色版"：

1. 下载官方 **Windows embeddable package (64-bit)**：<https://www.python.org/downloads/windows/>
2. 解压到 `SpaceSight\runtime\`，确认存在 `runtime\python.exe`
3. 直接双击 `start-spacesight.bat` 或 `SpaceSight.exe` —— 会优先使用这个运行时

> embeddable 包默认不带 `sqlite3`？—— 实际上 `_sqlite3.pyd` 是随包提供的，本项目只用标准库，
> 因此无需任何额外配置即可运行。

## 5. 排错清单

| 现象 | 原因 | 解决 |
|---|---|---|
| 双击 bat 一闪而过 | 没有可用的 Python | 在 cmd 里运行 `start-spacesight.bat` 看报错；按 §1.1 装 Python |
| 提示 `Python was not found ... Microsoft Store` | PATH 里只有 Store 占位别名 | 见 §1.1 的两种解决办法 |
| 浏览器打不开 / 空白 | 服务没起来，或端口不是你输入的 | 看控制台打印的「界面地址」，端口可能不是 8765 |
| `8765` 被占用 | 已有实例或别的程序占用 | 程序会自动顺延 8766/8767…；控制台会打印真实地址，也可看 `data\server.port` |
| 双击 `SpaceSight.exe` 没反应 | 找不到 Python，弹窗可能被挡住 | 看 `data\launcher.log`；先用 bat 确认能跑 |
| Windows 提示"未知发布者" | 本地编译的 exe 没有签名 | 属正常现象；也可以直接用 bat 启动 |
| 界面能开但没有任何数据 | 还没添加追踪目标 | 右上角「＋ 添加追踪」，或「✛ 大文件体检」 |
| 扫描很慢 | 机械硬盘 + 几十万小文件 | 先用「大文件体检」定位，再对具体目录建索引 |
| 某个目录显示 0 | 权限受限的系统目录 / 云盘占位文件 | 属正常；可用管理员身份运行试试 |
| 中文显示成方块 | 控制台字体/编码 | 项目已强制 UTF-8；换个终端（Windows Terminal）即可 |

日志位置：

```
data\server.log     服务日志（无控制台启动时）
data\launcher.log   启动器决策日志（选了哪个解释器、为什么不可用）
```

## 6. 数据、备份与卸载

| 操作 | 做法 |
|---|---|
| 数据在哪 | `SpaceSight\data\spacesight.db`（SQLite 单文件） |
| 备份 | 关服务后复制整个 `data` 目录 |
| 换电脑 | 复制整个 `SpaceSight` 目录；失效的追踪目标删掉重加（备注按路径保留） |
| 重置索引 | 关服务，删除 `data\spacesight.db*`（标注与索引一起清空） |
| 卸载 | 关服务，删除 `SpaceSight` 文件夹。**不写注册表、不留后台服务** |

多套独立数据：`python run.py --data-dir D:\ss-demo`。

## 7. 非 Windows 平台

后端（`app/`）是纯标准库，理论上可在 macOS/Linux 运行，但**安装察觉与盘符枚举依赖 Win32 API**，
在这些平台上：

- 注册表台账为空（`/api/apps` 返回 `registry_ok: false`）
- 进程监控退化为空集合
- 目录变更侦测只对显式添加的追踪根生效

也就是说：**手动添加 + 扫描 + 树/矩形图/备注 可用**，自动察觉不可用。
（欢迎 PR 移植 `detectors.py` 的 macOS/Linux 实现。）

## 8. 给二次开发者的最短路径

```text
app/server.py     路由与 API：想加接口从这里开始
app/store.py      SQLite 表结构与查询
app/scanner.py    目录扫描与体检算法
app/detectors.py  三路察觉逻辑（提供器可注入，便于测试）
web/app.js        前端全部逻辑（状态容器 S + 渲染函数）
```

改完前端直接刷新浏览器即可（静态文件 `no-store`）；改完后端需要重启服务。

提交前请跑：

```bat
python tools\selftest.py        :: 34 项
node tools\cdp-test.mjs ...     :: 可选，11 项
```

## 9. 把本项目发布到你自己的仓库（fork / 二次发布）

仓库自带一个**零依赖发布脚本**，只用 Python 标准库 + GitHub REST API，**不需要装 git / gh**：

```bat
publish-to-github.bat --dry-run         :: 先体检：待发布文件清单 + 隐私扫描（发现本机路径/用户名就中止）
publish-to-github.bat --repo my-name    :: 真正发布，会提示粘贴 token（不回显、不落盘）
```

- Token 权限：fine-grained 需要 **Contents: Read/Write** + **Administration: Read/Write**（+ **Workflows: Read/Write**，因为仓库含 .github/workflows/）；
  classic token 勾选 epo 和 workflow 即可
- 想先建私有仓库检查一遍：加 --private
- **空仓库的坑**：GitHub 不允许在"没有任何提交"的仓库上调用 Git Data API，
  git/blobs、git/trees、git/commits 都会返回 409 Git Repository is empty。
  脚本会自动用 Contents API 建一个"引导提交"（README.md）再继续，所以**不需要删仓库**。
  手动兜底也很简单：在网页上先给仓库创建一个 README，再重跑脚本。
- 对**已有内容的仓库**执行时，本次清单之外的文件会被删除（相当于整棵树覆盖），请先 --dry-run 看清单。
